// Extrage .so din JAR-urile natives în jniLibs/<abi>/ — rulat înainte de mergeJniLibFolders
tasks.register("extractNatives"){
 doLast{
  val nativesDir=file("src/main/jniLibs")
  configurations["natives"].resolve().forEach{jar->
   val n=jar.nameWithoutExtension
   val abi=when{
    n.contains("natives-armeabi-v7a")->"armeabi-v7a"
    n.contains("natives-arm64-v8a")->"arm64-v8a"
    n.contains("natives-x86_64")->"x86_64"
    n.contains("natives-x86")->"x86"
    else->return@forEach
   }
   val target=File(nativesDir,abi)
   target.mkdirs()
   ZipFile(jar).use{zip->
    zip.entries().asSequence().filter{it.name.endsWith(".so")&&!it.isDirectory}.forEach{entry->
     zip.getInputStream(entry).use{input->
      File(target,File(entry.name).name).outputStream().use{output->
       input.copyTo(output)
      }
     }
    }
   }
  }
 }
}
tasks.matching{it.name.startsWith("merge")&&it.name.endsWith("JniLibFolders")}.configureEach{dependsOn("extractNatives")}

# HiBlue – update0.0.9

**Fix de compilare** pentru build-ul Gradle Kotlin DSL din update0.0.8.

## Problema

`app/build.gradle.kts` folosea nume Java complet calificate (`java.io.File`,
`java.util.zip.ZipFile`) în corpul task-ului `extractNatives`, fără importuri
explicite la top. În Kotlin DSL, acest lucru produce erorile:

```
Unresolved reference: io
Unresolved reference: util
Cannot infer a type for this parameter
```

## Repararea

- Adăugate `import java.io.File` și `import java.util.zip.ZipFile` la top-ul
  fișierului `build.gradle.kts`.
- Înlocuite apelurile `java.io.File(...)` → `File(...)` și
  `java.util.zip.ZipFile(...)` → `ZipFile(...)`.
- Versiune bumped: `versionCode=10`, `versionName="0.0.9"`.

Niciun alt fișier nu se modifică. Tot restul din update0.0.8 rămâne neschimbat.
